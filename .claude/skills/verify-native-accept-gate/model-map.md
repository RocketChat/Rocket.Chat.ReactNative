# Model map

Maps each exported action and top-level variable in `native-accept-gate.ts` to the code it stands for. Line numbers are at the sync commit in [SKILL.md](SKILL.md). `sdk/` means `node_modules/@rocket.chat/sdk/lib/`.

## Actions

| Action                      | Code                                                                                                                                                                                                                                          | What the step is                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `RecoverSocket`             | `app/lib/services/voip/acceptNativeCall.ts:56` → `app/lib/services/socketHealth.ts:14` `shareRecovery` (`probe(2000)` at :30, `reopenNow()` at :34); `sdk/drivers/connection.ts:119` `reopenNow`, :206 `installTransport`                     | The probe succeeds (`alive`), or the SDK forces a new connection: `gen` goes up, in-flight requests are abandoned, the app emits `connecting`/`connected` and requests a resume login. Then both gate waits start, and `waitForLoginReady` latches `true` at once if `isLoginReady()` (`loginWait`).                                                                                                                                                    |
| `SendSubscription(s)`       | `sdk/drivers/ddpSubscriptions.ts:160` `sendSubscription`                                                                                                                                                                                      | The head of the per-id queue goes out as `{msg:'sub'}`. While offline (`link = "down"`, :164) it resolves with the record without sending.                                                                                                                                                                                                                                                                                                              |
| `SendLogin`                 | `app/lib/services/connect.ts:104-112` (`connected` → `loginRequest({resume})`) → `app/sagas/login.js:109` → `sdk/clients/Rocketchat.ts:20` `login` (REST first, then the DDP `login` method)                                                  | The DDP resume login leaves the app. Because REST comes first, it can be ordered after the gate's `sub`.                                                                                                                                                                                                                                                                                                                                                |
| `AppLogsInAgain`            | `app/sagas/deepLinking.js:316`, `app/views/SetUsernameView.tsx:87`, `app/lib/services/connect.ts:413` → `loginRequest` → `sdk/clients/Rocketchat.ts` `login`                                                                                  | `relogin` only, once: the app sends a login on a socket that is open and already logged in.                                                                                                                                                                                                                                                                                                                                                             |
| `ServerHandlesLogin(first)` | Server `login` method; monolith: Meteor `livedata_server.js` `_setUserId` (re-runs every named sub, buffers their `ready`s in `_pendingReady`, sends them in one frame); ddp-streamer: `ee/apps/ddp-streamer/src/methods/accounts.ts` `login` | The connection becomes authenticated and answers with the result. On monolith with active subs, a `ready` frame listing them comes first; `first` picks which id it lists first.                                                                                                                                                                                                                                                                        |
| `ServerHandlesSub`          | Monolith: Meteor ddp-server `livedata_server.js` `_namedSubs.has(msg.id)`. Streamer: Rocket.Chat `ee/apps/ddp-streamer/src/Server.ts` `subscribe`. Both: `packages/streamer/src/streamer.module.ts` `_publish` (`not-allowed`)                | Before login: `nosub` with an error. Active id on monolith: ignored. Otherwise: active, and `ready` is sent.                                                                                                                                                                                                                                                                                                                                            |
| `ReceiveLoginResult`        | `sdk/drivers/socket.ts:441` `login` → :444 `subscribeAll` (`sdk/drivers/ddpSubscriptions.ts:111`)                                                                                                                                             | Login result arrives. It queues a re-send for every subscription in `records` right now (`subscribeAll`).                                                                                                                                                                                                                                                                                                                                               |
| `ReceiveReady`              | `sdk/drivers/socket.ts:164` (`ready` → every id in `subs`), `sdk/drivers/ddpRequests.ts:145`, `sdk/drivers/ddpSubscriptions.ts:183` `rememberSubscription`, :50-52 `markReady`                                                                | If a `sub` for that id is in flight, it resolves and the record is (re)written. The `ready` listener (`markReady`, registered before the socket's id routing) records the attached Transport in `readyOn` for every id in the frame, with or without a record (`readyOnGen` = `gen`). It is the only place readiness is written, and it also covers a `ready` that lands after its `sub` expired. A frame's second id (`also`) is handled the same way. |
| `ReceiveNosubError`         | `sdk/drivers/ddpRequests.ts:145` `toError` → `sdk/drivers/ddpSubscriptions.ts:178` → :54 `forgetSubscription`                                                                                                                                 | The in-flight `sub` rejects with `DDPError`; the record and its `readyOn` are deleted.                                                                                                                                                                                                                                                                                                                                                                  |
| `LoginSuccess`              | `app/sagas/login.js:151` `loginSuccess` → `app/reducers/login.ts:62`; `app/lib/services/waitForLoginReady.ts:30`                                                                                                                              | `isAuthenticated` becomes true, and a pending `waitForLoginReady` resolves `true`.                                                                                                                                                                                                                                                                                                                                                                      |
| `MediaSubsWaitSettles`      | `sdk/drivers/driver.ts:152` `waitForNotifyUserMediaSubs` → `sdk/drivers/ddpSubscriptions.ts:83` `waitForStreamsReady` (checked at once, then every 100 ms)                                                                                    | The wait resolves `true` once both media records exist and each `ready` arrived on the attached Transport (`readyOnGen` = `gen`, link open). It sends nothing.                                                                                                                                                                                                                                                                                          |
| `AcceptDecides`             | `app/lib/services/voip/acceptNativeCall.ts:73-96`                                                                                                                                                                                             | `Promise.all` of both waits. Any `false` → `handleFailure` (:35), shown as `failed`. Otherwise `answerCall`, shown as `answered`, and `answeredLive` records whether the subscriptions were live at that moment. Runs as a microtask.                                                                                                                                                                                                                   |
| `TransportLost`             | `sdk/drivers/connection.ts:171` `transportLost`; `sdk/drivers/ddpRequests.ts:100` `abandonAll`; `app/lib/services/connect.ts:120` (`close` → `disconnectAction`)                                                                              | An unexpected close. Every in-flight `sub` rejects with `AbandonedRequest`, and `rememberSubscription` keeps its record, so it counts as `ok` for the gate. `meteor.connected` becomes false.                                                                                                                                                                                                                                                           |
| `Reopen`                    | `sdk/drivers/connection.ts` `scheduleReopen` → `start`; `app/lib/services/connect.ts:100-112`                                                                                                                                                 | A new connection on a fresh server session. The app requests a resume login.                                                                                                                                                                                                                                                                                                                                                                            |
| `GateDeadline`              | `acceptNativeCall.ts:74-75` (8000 ms on both waits)                                                                                                                                                                                           | Fires once, and only when nothing else can move (healthy-server assumption). Each wait that is still pending resolves `false` (`mediaSubsWait`, `loginWait`), and `AcceptDecides` then decides. `deadlinePassed` records it.                                                                                                                                                                                                                            |
| `ExpiredWait(s)`            | `sdk/drivers/ddpRequests.ts:139`; `sdk/drivers/ddpSubscriptions.ts:175-176`                                                                                                                                                                   | The SDK's 10s deadline on a `sub` with no answer on the way (ignored by the server, or its `ready` not routed to it). The record is kept, without `readyOn`. The `late` scenarios start just after one already expired.                                                                                                                                                                                                                                 |

`noMicrotaskPending()` keeps every other client step from running while `MediaSubsWaitSettles` or `AcceptDecides` is enabled. In the code, both are promise continuations that run before the next frame or event.

## Variables

| Variable                                                                 | Code                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SERVER`, `SOCKET`, `MAX_DROPS`, `LATE_READY`, `RELOGIN` (`scenario.ts`) | Fixed per scenario: the server type, whether `probe(2000)` succeeds, how many transport losses the run allows, whether the run starts with media-signal's `sub` expired (record kept, not ready) and its `ready` still on the way, and whether the media subs start unsent with one extra login allowed. `check.sh` writes one `scenario.ts` per scenario |
| `records`                                                                | `DDPSubscriptions.records` (`sdk/drivers/ddpSubscriptions.ts`)                                                                                                                                                                                                                                                                                            |
| `queue`, `inFlight`                                                      | `DDPSubscriptions.subscriptionRequests` chain per id, and its written request                                                                                                                                                                                                                                                                             |
| `link`, `gen`                                                            | `Connection.transport` / `offline` (`sdk/drivers/connection.ts:94`). `gen` counts connections; it is not `closesTaken`, which only counts `close()`                                                                                                                                                                                                       |
| `login`, `loginReady`                                                    | Resume login progress; `isLoginReady()` = `login.isAuthenticated && meteor.connected` (`app/lib/services/waitForLoginReady.ts:4`)                                                                                                                                                                                                                         |
| `loginWait`                                                              | The latched result of `waitForLoginReady` for this gate: `pending`, `true`, or `false` after its timeout                                                                                                                                                                                                                                                  |
| `serverSubs`, `serverUser`                                               | The server session's active subscription ids and its `userId`                                                                                                                                                                                                                                                                                             |
| `toServer`, `toClient`                                                   | The connection's frames in each direction, FIFO. A `ready` frame's `sub` and `also` are its `subs[0]` and `subs[1]`                                                                                                                                                                                                                                       |
| `reloginSent`                                                            | Whether `AppLogsInAgain` already ran                                                                                                                                                                                                                                                                                                                      |
| `gate`, `mediaSubsWait`                                                  | `acceptNativeCallWithReadiness` progress, and the `waitForStreamsReady` promise                                                                                                                                                                                                                                                                           |
| `readyOnGen`                                                             | `DDPSubscriptions.readyOn` (`sdk/drivers/ddpSubscriptions.ts`): the Transport each `ready` arrived on, as the connection count `gen`                                                                                                                                                                                                                      |
| Request origin `"gate"`                                                  | No action sends one at the sync commit. A change that makes the gate send a `sub` again queues it with origin `"gate"`, which `GateSendsNoDuplicateSub` watches                                                                                                                                                                                           |
| `answeredLive`, `gateSentDuplicate`, `deadlinePassed`                    | History variables for the invariants, with no code counterpart                                                                                                                                                                                                                                                                                            |
