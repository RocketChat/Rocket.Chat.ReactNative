## Findings considered and rejected (do not re-audit)

- **BUG-01 "refcount starvation in goRoom warm-up":** rejected. Every acquire pairs exactly one release (warm-up → `runAfterInteractions` grace release; mount → unmount). Double-tap stays balanced. Worst case is a lost warm-up benefit (store re-created at mount), never a torn-down live store.
- **BUG-04 "jump-to-message race on slow anchor resolve":** not worth doing — `useScroll`'s retry loop already covers the window.
- **`Components/` vs `components/` case-duplicate directory:** illusion of macOS case-insensitive FS in diff grouping; `git ls-files` shows fully renamed at HEAD. Not a finding.
- **RoomMessageActions stale room (PERF-01 candidate):** vetted out — reads room fields at action time (sheet open), model mutated in place gives fresh reads; no stale render output. Re-raised by iteration-2 audit as CORRECT-01 and re-rejected: all `room.*` reads in `MessageActions` sit inside `getOptions`/`showMessageActions` (ref-invoked at long-press), and `isReadOnly` arrives as a recomputed RoomView-state prop.
- **DEBT-03 "room+roomUpdate pairing idiom duplicated 3×, extract shared factory":** rejected iteration 4. The useHeader and index.tsx sites need the `roomUpdate` VALUE (effect dep / prop), not a re-render pairing — a shared hook can't serve them. Only 2 true duplicates remain (useRoomWithUpdate, useComposerRoom), each 5 lines over a different store/context and pinned by its own regression test; a generic factory adds more indirection than it removes.
- **Iteration-6 PERF-01 (MessageRow fan-out):** vetted — accepted but REFRAMED as a correctness bug (plan 010). Compiled output shows `isIgnored(item)`/`getBadgeColor` cached on the stable `room` ref, so the roomUpdate pairing re-render serves stale values; fan-out is the secondary symptom. RoomFooter vetted safe (reads room fields inline in conditions / property-level cache guards); ComposerInput vetted safe (compiler leaves placeholder computation unmemoized).
- **Iteration-6 PERF-02 (unverifiable compiler stability of plain handlers):** vetted — accepted and found WORSE than reported: 4 annotated units (`RoomView/index.tsx`, `useRoomLifecycle.ts`, `useOmnichannelPermissions.ts`, `useScroll.ts`) are silently SKIPPED by the compiler because of `react-hooks/exhaustive-deps` suppressions (verified with `panicThreshold: 'all_errors'`). Guardrail = plan 011; de-suppression = 012 (next iterations).
- **PERF-02 goRoom warm-up serialized behind `getSubscriptionByRoomId` await:** rejected iteration 2 — warm-up must stay in `navigate()` (deepLinking saga uses `navigateToRoom`), so starting earlier means double-warm or flag-threading; the gain is bounded by one indexed WatermelonDB query (~ms) ahead of a ~300ms transition. Complexity > benefit.
